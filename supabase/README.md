# Dedicated city account service

**Deployment status: prepared; not connected.** `simulation/account_config.gd` intentionally contains no URL or public key until a separate Nottingham City project is created in the selected organisation. The existing Academy database must not be changed.

The generated migration in `migrations/` creates one owner-scoped JSON snapshot per authenticated city account. RLS permits an authenticated owner to read only their own row. Direct client writes are revoked; the Edge Function verifies Supabase Auth and performs revision-checked writes. Only its server environment uses `SUPABASE_SERVICE_ROLE_KEY`; a publishable key is the only key shipped in the game.

The game creates a random sixteen-character private code. A SHA-256-derived synthetic account address and that code authenticate through Supabase Auth. The code is removed from uploaded city snapshots. Keep it private: it is the recovery credential, including for another browser. The Account app requires explicit confirmation before taking over an active session. A 90-second single-writer lease and optimistic revisions reject stale writes rather than overwriting another device's purchases. The old game pauses on a conflict and keeps its local save. Reconnecting loads a newer remote snapshot before resuming. Saves are local-first; there is no offline income, multiplayer economy, anti-cheat guarantee, or fully authoritative banking service.

To activate, create the authorised **separate game project**, apply the generated migration, deploy `functions/city-account/index.ts` with JWT verification disabled at the gateway (the function authenticates protected actions itself), and set the project's URL and publishable key in `simulation/account_config.gd`. Verify two different accounts cannot read each other's rows, test browser recovery and conflicting-session takeover, and run database advisors before shipping the configured build. No billing, project creation or database mutation is performed by the repository's GitHub Actions.

Run `node --test supabase/tests/city_account.test.mjs` for snapshot validation, account isolation, recovery, controller-only scope, lease expiry, concurrent login, stale revisions and repeated-create protection. The cloud service is optional for local gameplay. Private-code controller pairing works independently through a hashed PeerJS ID and HMAC challenge; the six-character temporary QR code remains available for a guest controller.
